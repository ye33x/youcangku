# 优果仓 · 界面演示 Demo

纯前端演示工程，**不请求任何后端接口**，所有数据来自 `src/mock/db.js` 的静态数据，
在浏览器内存中增删改，刷新即恢复（也可用演示面板一键重置）。

用途：评估整体界面布局、页面跳转关系与核心操作流程是否合理。

## 运行

```bash
cd demo
npm install
npm run dev      # http://localhost:5175
```

## 三端入口

| 端 | 账号 | 密码 | 入口 |
|---|---|---|---|
| 用户端 | `user01` / `user02` | `123456` | `/user/home` |
| 商家端 | `guo_shop` / `nuts_shop` | `123456` | `/merchant/dashboard` |
| 管理端 | `admin` | `123456` | `/admin/dashboard` |

登录页有三张角色卡，点一下就自动填入对应账号。顶栏「演示控制」可随时切换身份。

## 建议的演示路径

1. **用户主链路**：登录 → 首页（看推荐位与推荐理由）→ 商品详情 → 加入购物车 → 购物车改数量/勾选 → 结算 → 提交订单 → 订单页「去支付」→ 确认收货 → 提交评价（待审核）
2. **商家链路**：切到商家端 → 工作台看待办 → 订单管理「发货」→ 售后处理「同意/拒绝」→ 评价管理「回复」
3. **平台链路**：切到管理端 → 评价审核通过（回用户端商品详情能看到该评价已展示）→ 订单管理对纠纷单做平台裁定 → 分类管理删除有商品的分类（触发禁止删除提示）→ 操作日志筛选

## 演示面板能做什么

点击顶栏「演示控制」打开抽屉，可以实时调整：

- **接口延迟** 0–2000ms：调到 1500ms 以上能清楚看到骨架屏
- **模拟错误率** 0–100%：调高后刷新页面，可以看到错误提示与「重新加载」
- **空数据模式**：开启后所有列表返回空，用来检查空状态文案与引导按钮
- **角色切换 / 快捷入口 / 重置数据**

## 已覆盖的界面状态

| 状态 | 出现位置 |
|---|---|
| 加载中（骨架屏） | 首页推荐、商品列表、订单列表、商家列表、日志 |
| 空状态 | 购物车为空、搜索无结果、订单为空、售后为空、评价为空、收藏为空 |
| 错误 + 重试 | 任意列表（调高错误率）、商品详情不存在（访问 `/user/product/999`） |
| 成功反馈 | 加购、下单、支付、发货、审核、保存资料 |
| 二次确认 | 取消订单、删除地址、发货、同意售后、禁用账号、删除分类 |
| 表单校验 | 登录空账号/错密码、发布商品缺名称、新增地址缺字段、评价空内容 |
| 禁用态 | 零库存商品（`/user/product/16`）的加购与立即购买按钮 |
| 权限跳转 | 未登录访问任意页面 → 登录页；角色不符 → 跳回自己主页 |

## 目录

```
demo/src/
├── mock/          # 静态数据 + 模拟接口（延迟 / 错误注入 / 分页）
├── store.js       # 登录态、购物车、订单、评价等前端状态
├── router/        # 三端路由与角色守卫
├── layouts/       # 用户端店铺布局 / 商家+管理端控制台布局
├── components/    # 商品卡、异步状态容器、演示控制面板
└── views/         # user / merchant / admin 三组页面
```

> 注意：本 Demo 只用于界面与流程评审，**没有真实鉴权、数据库与业务校验**，
> 所有「成功/失败」都是前端模拟。真实实现见仓库 `server/` 与 `web/`。
